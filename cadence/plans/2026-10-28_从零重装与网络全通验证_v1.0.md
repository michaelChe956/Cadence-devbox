# 从零重装 + 网络全通验证（Windows 宿主）

> 目标：把机器恢复到「本次所有操作之前」，再全新安装一遍，最后逐条验证网络。
> 对应改动：OpenSpec change `unify-devbox-container-and-vpn-services`（commit `322d491`）

---

# 第 0 步：先选回退档位

| 档 | 做什么 | 代价 |
|---|---|---|
| **A｜彻底零** | relay 通道拆除 + `podman machine rm`（容器/卷/镜像/网络全没） | 中间件数据（mysql/redis 的库）、agent 登录态、Maven 缓存、JDK 选择**全部丢失** |
| **B｜只回退本次** | relay 通道拆除 + 删掉 devbox 容器（卷与数据保留） | 数据都在，但机器不是"全新" |
| **C｜只回退仓库** | 仓库回到改动前，机器状态不动 | 适合单独验证"老版本还能不能用" |

先做 A 或 B，第 3 步做完再决定要不要 C。

---

# 第 1 步：回退到「什么都没操作」

## 1.1 先拆 relay 通道（**必须在删 machine 之前**）

Windows 的 portproxy 规则存在 Windows 自己身上，`podman machine rm` 不会清它——所以要先拆：

```powershell
cd D:\testpodman\Cadence-devbox
powershell -ExecutionPolicy Bypass -File .\devbox\relay.ps1 -InstallDir D:\testpodman\cadence -Teardown
```

期望输出：逐条列出删除的 portproxy、VM 侧单元、映射文件、`relay.json`；末尾「teardown 完成，两侧已还原到通道建立前」。

验证确实清干净了：

```powershell
netsh interface portproxy show all
podman machine ssh 'sudo nft list table ip cadence_dnat; systemctl list-units "cadence-relay*" --no-pager'
```
期望：portproxy 列表为空（或只剩你自己建的规则）；`nft list` 报「No such table」；无 cadence-relay 单元。

## 1.2 删掉容器（A 档：删 machine）

```powershell
# A 档：彻底归零（容器、卷、镜像、网桥全没）
podman machine stop
podman machine rm
# 之后 install.ps1 会自动重新 init 并起 machine

# B 档：只删容器（保留卷与中间件数据）
podman rm -f cadence_devbox cadence_devbox_1 devbox devbox-old-20261027
podman-compose -f D:\testpodman\cadence\stack\compose.yaml down
```

## 1.3 删安装目录（A 档建议，连密钥一起清掉）

```powershell
Rename-Item D:\testpodman\cadence D:\testpodman\cadence.bak-20261028
```
（改名而非删除——出问题能一秒回退。）

## 1.4 仓库侧（选做，C 档）

```powershell
git -C D:\testpodman\Cadence-devbox log --oneline -3
git -C D:\testpodman\Cadence-devbox revert --no-edit 322d491   # 保留历史地撤销
# 或：git -C D:\testpodman\Cadence-devbox reset --hard HEAD~1  # 彻底丢弃该提交
```

# 第 2 步：全新安装

## 2.1 前提

- Podman Desktop 已装、WSL2 可用（`podman machine list` 能看到 machine）
- **aTrust VPN 在线**（第 4 步的公司侧验证全靠它）

## 2.2 跑安装器

```powershell
cd D:\testpodman\Cadence-devbox
powershell -ExecutionPolicy Bypass -File .\devbox\install.ps1
```

首次运行会依次：

1. 检测 podman / machine（没 machine 会自动 init、没运行会自动 start）
2. 生成安装目录 → **手工编辑 `cadence-box.yaml` 填 provider 端点/key/模型 + git.name/email**（从备份复制也行：`D:\testpodman\cadence.bak-20261028\cadence-box.yaml`）
3. 写 registry mirror 到宿主与 machine 两侧
4. 预建 external 卷 → 拉镜像（872MB，国内源几分钟到十几分钟）→ 起中间件与 devbox
5. 打印收尾提示

## 2.3 装完自检

```powershell
podman ps -a --format "{{.Names}}  {{.Status}}"
```
期望：**只有一个** devbox 容器，名字 `cadence_devbox`，状态 Up；另有 `cadence_mysql_1`、`cadence_redis_1`（healthy）。

```powershell
podman exec cadence_devbox bash -c "claude --version && stack status && ls /workspace"
```
期望：五端 CLI 版本号、`stack status` 显示 mysql/redis 运行、`/workspace` 里能看到你的仓库。

# 第 3 步：恢复 VPN 侧通道（relay）

全新安装后 `relay.json` 不存在 → 通道要重建。**省事做法：先手写 relay.json**，再跑 setup（保留项沿用原端口，不会重新推导）。

```powershell
$relay = @'
{
  "version": 1,
  "gateway": "10.89.0.1",
  "services": [
    {"name":"mysql","remoteHost":"10.129.12.75","remotePort":3306,"hostPort":13306,"vmPort":23306},
    {"name":"redis","remoteHost":"10.129.117.17","remotePort":6379,"hostPort":16379,"vmPort":26379},
    {"name":"mysql_log","remoteHost":"10.129.12.73","remotePort":3306,"hostPort":13307,"vmPort":23307},
    {"name":"mq","remoteHost":"10.129.12.53","remotePort":9876,"hostPort":19876,"vmPort":29876},
    {"name":"elasticsearch","remoteHost":"10.130.7.181","remotePort":5244,"hostPort":15244,"vmPort":25244},
    {"name":"elasticsearch_1","remoteHost":"10.130.7.69","remotePort":5244,"hostPort":15245,"vmPort":25245},
    {"name":"elasticserarch_2","remoteHost":"10.130.7.64","remotePort":5244,"hostPort":15246,"vmPort":25246},
    {"name":"gitlab","remoteHost":"198.18.0.2","remotePort":80,"hostPort":10080,"vmPort":20080,"host":"gitlab.tianti.tg.unicom.local"}
  ]
}
'@
New-Item -ItemType Directory -Force D:\testpodman\cadence | Out-Null
Set-Content -Encoding ascii D:\testpodman\cadence\relay.json $relay
```

> `gitlab` 的 IP 是 aTrust 假 IP——若换过 VPN，先 `nslookup gitlab.tianti.tg.unicom.local` 确认仍是 `198.18.0.2`，不是就改这一处。

然后：

```powershell
powershell -ExecutionPolicy Bypass -File .\devbox\relay.ps1 -InstallDir D:\testpodman\cadence
```

问答：**保留已有序号（回车）→ 要修改的已有序号（回车）→ 新增（回车）**。

期望：8 条「预检通过」→ 8 条 portproxy → 映射表 8 条 → **16 条探活 OK**（8 条桥接地址 + 8 条真实地址「DNAT 生效」）。

# 第 4 步：网络逐项验证

## A. 容器 → 本地 stack 中间件（compose 网络内直连）

```powershell
podman exec cadence_devbox mysql -h cadence_mysql_1 -u root -pcadence123 -e "SELECT 1"
podman exec cadence_devbox redis-cli -h cadence_redis_1 -a cadence123 PING
```
期望：`1` / `PONG`。

## B. 容器 → stack 暴露端口（宿主回环）

```powershell
podman exec cadence_devbox bash -c 'timeout 5 bash -c "echo > /dev/tcp/127.0.0.1/3306" && echo CONNECT-OK'
```
期望：`CONNECT-OK`。

## C. 容器 → VPN 侧中间件（真实地址，走 DNAT）★核心

```powershell
podman exec cadence_devbox mysql -h 10.129.12.75 -P 3306 -u root -p -e "SELECT 1"
podman exec cadence_devbox redis-cli -h 10.129.117.17 -p 6379 --askpass PING
podman exec cadence_devbox bash -c 'for p in 10.129.12.53:9876 10.130.7.181:5244 10.130.7.69:5244 10.130.7.64:5244; do h=${p%:*}; pt=${p#*:}; timeout 5 bash -c "echo > /dev/tcp/$h/$pt" && echo "OK $p" || echo "FAIL $p"; done'
```
期望：`SELECT 1` 返回 `1`；redis `PONG`；四个端口全 `OK`。

## D. 容器 → VPN 侧中间件（桥接地址，绕过 DNAT 验证 relay 本体）

```powershell
podman exec cadence_devbox bash -c 'for p in 10.89.0.1:23306 10.89.0.1:26379 10.89.0.1:29876 10.89.0.1:25244 10.89.0.1:25245 10.89.0.1:25246 10.89.0.1:20080; do timeout 5 bash -c "echo > /dev/tcp/${p%:*}/${p#*:}" && echo "OK $p" || echo "FAIL $p"; done'
```
期望：7 个全 `OK`。

## E. 容器 → GitLab（HTTP 80，走 DNAT）★本次新增场景

```powershell
podman exec cadence_devbox bash -c "getent hosts gitlab.tianti.tg.unicom.local; timeout 5 bash -c 'echo > /dev/tcp/198.18.0.2/80' && echo CONNECT-OK; curl -s -o /dev/null -w '%{http_code}\n' 'http://gitlab.tianti.tg.unicom.local/ibos/ibosdev/authority.git/info/refs?service=git-upload-pack'"
```
期望：`198.18.0.2` / `CONNECT-OK` / `401`（401 = 通路通、只是没带凭据）。

```powershell
podman exec -it cadence_devbox bash
# 容器内：cd /workspace/authority && git fetch origin --prune
```

## F. 容器 → 公网（构建源）

```powershell
podman exec cadence_devbox bash -c "curl -s -o /dev/null -w 'npmmirror %{http_code}\n' https://registry.npmmirror.com; curl -s -o /dev/null -w 'aliyun-maven %{http_code}\n' https://maven.aliyun.com/repository/public/"
```
期望：两个都 `200`。

## G. 容器 → 宿主（端口映射 3000/8080）

```powershell
podman exec cadence_devbox bash -c 'timeout 5 bash -c "echo > /dev/tcp/host.containers.internal/3000" && echo OK || echo FAIL'
```
（容器内没起服务时 FAIL 属正常——这一步验的是路由；起个服务再测更有意义。）

## H. Windows 宿主 → 容器内服务（走 compose 发布的端口 8080）

```powershell
# 容器内起一个临时监听（8080 是 compose 已发布的端口，宿主机 127.0.0.1:8080 可达）
podman exec -d cadence_devbox bash -c "python3 -m http.server 8080 --bind 0.0.0.0"
Start-Sleep 2
curl.exe -I http://127.0.0.1:8080/
podman exec cadence_devbox pkill -f "http.server 8080"
```
期望：`HTTP/1.0 200 OK`。

## I. Windows 宿主 → 公司服务器直连（不经 relay）

```powershell
curl.exe -I -m 8 http://gitlab.tianti.tg.unicom.local/
Test-NetConnection 10.129.12.75 -Port 3306
```
期望：302/200；TcpTestSucceeded : True。

## J. 容器内 DNS

```powershell
podman exec cadence_devbox bash -c "getent hosts gitlab.tianti.tg.unicom.local; getent hosts registry.npmmirror.com"
```
期望：第一条 `198.18.0.2`（假 IP），第二条公网真 IP。

## K. 容器内运维通道（docker.sock）

```powershell

```
期望：能看到 `cadence_mysql_1`、`cadence_redis_1`、`cadence_devbox`。

## L. relay 逐跳体检

# 第 5 步：哪一步挂了怎么定位

| 现象 | 最可能的原因 | 先查 |
|---|---|---|
| C/E 全 FAIL，D 也 FAIL | relay 通道没建起来 | L 的 hop1/hop2/hop3 输出 |
| D 通、C 不通 | DNAT 规则没生效 | `podman machine ssh 'sudo nft list table ip cadence_dnat'` |
| C/E 通、F 不通 | 容器出网被拦（与 relay 无关） | 容器内 `curl -I https://registry.npmmirror.com` |
| E 通但 git fetch 失败 | 凭据问题（不是网络） | 容器内 `git fetch` 的报错是不是 401/403 |
| J 第一条不是 198.18.0.2 | 假 IP 变了 | Windows 上 `nslookup gitlab.tianti.tg.unicom.local`，同步改 relay.json 再重跑 setup |
