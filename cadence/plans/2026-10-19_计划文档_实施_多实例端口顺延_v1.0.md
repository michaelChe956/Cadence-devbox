# 多实例端口顺延与配置管理（relay）实施 Plan v1.0

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans 按任务逐项实施。步骤用 `- [ ]` 跟踪。

**Goal:** relay.ps1 端口分配从"单远端端口静态推导"升级为"占用感知的顺序分配 + 自动顺延"（多套同远端端口环境并存），并补齐配置管理闭环：`-List` 只读查询与交互修改（改址/显式改端口）。

**Architecture:** 不变——两跳中继（Windows portproxy → mirrored 回环 → VM socat 绑网桥网关）。本 change 只动宿主侧 relay.ps1 的端口分配与问答/查询层；relay-vm.sh 端口经 env 服务表传入，零改动。

**Tech Stack:** PowerShell 5.1 兼容 / pytest（AST 抽取 + 桩环境行为回归）。

**Spec:** `openspec/changes/improve-relay-service-config/`（proposal/design/specs/tasks 四产物，2026-10-19）。

## Global Constraints

- 顺延规则（2026-10-19 用户裁决）：hostPort=远端+10000 起、vmPort 恒为 hostPort+10000；候选（host 或 vm 任一）命中已分配端口或 stack 发布端口（3306/6379/5672/15672/9000/9001/3000/8080）→ 整体 +1 重试
- 分配顺序：保留项在前、参数项次之、新增项最后（修改项按原序重分配）；结果确定、重跑稳定、relay.json 顺序保持
- 保留项沿用 relay.json 旧端口不重推导；新分配只影响新增/参数/交互修改项
- 远端端口 1-45535；顺延后 hostPort ≤55535（vmPort 恒 ≤65535），越界 Die 说明
- 用户可见行 ≤100 字符；PS 多行块用 @() 数组禁 here-string；relay.ps1 保持 UTF-8 BOM + LF
- 禁止 TcpClient 字面量（终端管控红线，测试钉住）
- 不运行 tests/lint/build（controller 统一）；不 commit 不 push

## Review Focus

1. 双 3306 实例（mysql + mysql_log）→ 13306/23306 与 13307/23307 并存，不再 Die「端口同时属于」
2. 远端 rabbitmq 5672 → 自动越过 15672 得 15673/25673（原"显式拒绝撞点"逻辑删除）
3. 全保留重跑 → 端口/顺序零漂移（占用表先建、保留项直接沿用）
4. 修改问答：改址端口不变（无冲突时推导=旧值）；显式端口校验范围/撞栈/撞已分配，违反 Die 说明
5. `-List`：只读 relay.json（gateway 优先取留痕，legacy 现取），无文件 Die「通道未建立」，不探活
6. 修改序号必须在保留列表内；-Status/-Teardown/-List 三开关互斥
