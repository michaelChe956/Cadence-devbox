# 远端中间件一键通道（relay）实施 Plan v1.0

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans 按任务逐项实施。步骤用 `- [ ]` 跟踪。

**Goal:** 实现 `devbox/relay.ps1` + `devbox/relay-vm.sh` 一键拉通/查询/拆除容器到宿主 VPN 侧远端中间件（mysql/redis）的通道。

**Architecture:** 两跳中继：Windows netsh portproxy（仅 127.0.0.1）→ mirrored 回环 → VM 内 socat（仅绑 podman 网桥网关）。宿主 PS 脚本经 `podman machine cp/ssh` 驱动 VM 副脚本，配置留痕 `<InstallDir>/relay.json`。

**Tech Stack:** PowerShell 5.1 兼容 / bash + socat / pytest 结构测试 / ShellCheck。

**Spec:** `openspec/changes/add-remote-middleware-relay/`（proposal/design/specs/tasks 四产物，2026-10-10 修订版 commit dffd409）。

## Global Constraints

- 服务表：mysql hostPort=13306 vmPort=23306；redis hostPort=16379 vmPort=26379；与 compose 发布端口（3306/6379/5672/15672/9000/9001/3000/8080）零重叠
- 面向用户输出的命令行 ≤100 字符；PS 多行块用 @() 数组，不用 here-string
- VM 操作只用"cp 文件 + ssh sudo bash <file>"，禁止内嵌长命令字符串
- portproxy 只监听 127.0.0.1；socat 只绑网桥网关地址（`podman network inspect cadence_default` 动态发现）
- VM 持久化：systemd 优先（运行时探测 `systemctl is-system-running`），失败回退 wsl.conf [boot] 钩子；两条路径都用 `/etc/cadence-relay.env` + 幂等 pkill 重启
- 平台守卫：Provider=wsl 且 Running；非管理员自动 RunAs 重启自身
- 全部 VM 内自有文件用 `cadence-relay` 前缀；teardown 只删留痕内条目

## Review Focus

1. 端口被存量手搭中继占用（如 socat-mysql-relay）→ setup 须报告占用者并经确认后接管（spec：存量通道冲突检测）
2. 非交互 `systemctl` 报 Transport endpoint is not connected → relay-vm.sh 运行时探测并回退 boot 钩子
3. relay.json 缺失/损坏 → 问答重建，不崩（spec：交互式配置与留痕）
4. podman 网络未创建（stack 未起）→ 网关发现失败给明确指引，不留半配置
5. devbox 容器名差异（install.ps1 的 `devbox` vs compose 的 `cadence_devbox_1`）→ 探测两名，都没有则 Die

**Interfaces:**
- Consumes: Task 2 的 relay-vm.sh 三子命令与 env 行格式；`podman network inspect cadence_default` 的 `.Subnets[0].Gateway`
- Produces: `relay.json`（`{"version":1,"services":[{name,remoteHost,remotePort,hostPort,vmPort}]}`）；调用方：README §2.6 文档命令

- [ ] **Step 1: 实现骨架**：param 块 + Info/Warn/Die（照 install.ps1 风格）+ 平台守卫（podman machine inspect：Provider≠wsl → Die"仅支持 WSL 后端"；State≠Running → Die 先启 machine）+ 管理员检测（WindowsPrincipal，非管理员 `Start-Process -Verb RunAs` 带原参数重启并 exit）+ relay.json 读写（损坏则当作不存在）+ 交互问答（回显旧值，回车保留；`-MySQL/-Redis "host:port"` 参数覆盖，正则校验）
- [ ] **Step 2: 实现 setup**：顺序 = 守卫 → 管理员 → 问答/载配置 → 远端预检（TcpClient 3s，失败 Die"请先连接 VPN"，此时尚无任何改动）→ 网关发现（stack 未起则 Die）→ portproxy 幂等写入（先 delete 同 listenport 再 add，仅 127.0.0.1）→ 渲染 env（ASCII）+ `machine cp` 两文件 + `machine ssh sudo bash relay-vm.sh setup`（exit 3 冲突 → 回显占用者、确认 Y 后带 --force 重跑）→ 容器内探活（容器名先 `devbox` 后 `cadence_devbox_1`，都没有 Die）→ 打印连接表（`mysql → <gw>:23306` 形态，Write-Host 每行 ≤100 字符）
- [ ] **Step 3: 实现 -Status / -Teardown**：Status = portproxy 规则解析 + `machine ssh ... status` + 容器探活 + 宿主到远端 TcpClient，远端不通而中继正常 → 提示"VPN 未连"；Teardown = 回显清单（relay.json 条目 + VM cadence-relay* + socat 包）二次确认 → netsh delete（按留痕端口）+ `relay-vm.sh teardown` + 删 relay.json
