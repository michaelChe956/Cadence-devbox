# OpenJDK 8 按需安装与持久切换设计

## 状态与范围

本设计已经审阅确认；对应 OpenSpec 变更 `persistent-jdk-selection`，现有契约已按本设计对齐。尚未编写实施 Plan、实测安装或修改实现。

已确认的用户需求：镜像内置 Java 21 为首次默认值；容器内手动选择后，未再次指定时沿用上次版本；不弹菜单；交互及非交互新命令统一生效；不做 Skill。新增约束：目标是 **OpenJDK 8 的完整 JDK**，实施时先实测可正常安装，再开发切换机制。

## 现状与目标

当前 `devbox/Dockerfile` 通过 USTC 的 Adoptium apt 源只安装 Temurin 21；`devbox/compose.yaml` 为代理配置和构建缓存使用 external 卷，但无 JDK 持久卷。`devbox/entrypoint.sh` 写入 `.bashrc`，直接 `docker exec` 执行的非交互命令不会读取它。

目标是单张默认镜像加容器内 `jdk` 命令，而不是按 JDK 版本维护多张镜像。支持首次自动用 21、按需取得 OpenJDK 8、保存选择、切回 21。已运行的 JVM 不受切换影响。

## 首个实施门槛：先实测安装 OpenJDK 8

此门槛排在新增卷、修改 PATH、编写 `jdk` 命令之前。先在与目标镜像相同的 Ubuntu 24.04、CPU 架构、容器用户权限和中国大陆网络条件下，核对候选 OpenJDK 8 **发行版与具体构建**、包格式、下载端点、可信校验来源、许可及可用性。下载后核对 SHA-256，安装到临时隔离位置，并实际运行 `java -version` 和 `javac -version`：两者须为 8，且确认包含编译器而非仅 JRE。记录镜像来源、具体版本、哈希、验证命令与结果；不要把一次 HTTP 200 当作安装成功。

门槛未通过时停止后续实施，保留现有 Java 21，不通过关闭校验或悄悄改用不可信代理来绕过。若官方与国内来源均不可用，先报告证据及替代来源，修订设计/契约后再推进。**尚未实测，也尚未承诺任何具体下载地址可用。**

“OpenJDK 8”描述实现和主版本，不唯一指定发行商。Temurin 8 是一个 OpenJDK 8 发行版，且与内置 Temurin 21 同系列，宜作为首个待测候选；如果用户要求特定发行商（例如发行商原版或其他构建），须先确认，不能以 Temurin 代替其明示要求。最终发行版和构建号应在实测证据与用户确认后写入契约及实施 Plan。

## 组件与数据流

1. **持久状态**：增加独立 external 命名卷，保存额外安装的 JDK 和一个 `current` 选择。新卷首次初始化指向内置 21；再次进入或重建只验证和保留有效选择，不覆盖它。卷由安装器预创建，普通容器用户有写入权限。
2. **固定环境入口**：镜像向所有新进程提供固定 `JAVA_HOME`（指向 `current`）和优先于系统 Java 的 `current/bin` PATH；不能只在 `.bashrc` 配置。`jdk list` 从实际选择列出内置/额外安装版本和当前版本；`jdk use 8` 安装缺失版本后切换，`jdk use 21` 切回。非交互 `docker exec … java` 以及 Maven、Gradle 须能读到同一 JDK。
3. **下载与发布**：仅允许经验证支持的版本及架构。下载到卷内临时位置，从独立可信来源核对哈希，检查解包路径及 `bin/java`、`bin/javac` 的实际版本，成功后发布安装目录，最后原子替换 `current`；失败不改变现有选择，不静默回退未知代理。下载源可显式配置，默认源仅在实测可达且校验可信后写入。
4. **生命周期**：首次初始化无菜单；重建保留卷。升级镜像时若内置 JDK 21 目标路径改变，需识别并迁移指向内置版本的选择；如果额外安装版本失效或选择损坏，应明确报错，不擅自重置为 21。回滚旧镜像不删除新卷，但旧镜像不承诺读取新选择。

## 设计取舍与风险

- **固定路径而非修改每个 shell 环境**：覆盖直接执行的非交互命令；代价是某些进程若解析并缓存旧 JDK 的真实路径，不能在进程内热切换。切换影响后续新命令，不改变已运行的 JVM；运行中的构建若再启动 Java 子进程可能混用版本，应避免在构建中切换。
- **单卷状态而非全局修改系统 Java**：能跨容器重建保持选择，并减少对内置环境的修改；代价是 Compose、安装脚本和手工升级说明必须同步增加卷。
- **先下载验真再实现持久切换**：先消除国内网络和发行物可用性的关键不确定性；即使实验成功，也须保留运行期下载失败时原版本不变的行为。
- **可信校验优先于自动兜底**：从未经验证的镜像同时取得包和哈希不能单独证明真实性；官方元数据不可用时明确失败，而不是默认关闭验证。

## 验收与阶段边界

实施前先交付安装实测证据：容器内 OpenJDK 8 的 `java`、`javac` 输出与可信哈希匹配。通过后才编写或执行持久切换实现；验证首次 21、`jdk use 8`、`jdk list`、非交互与交互 `java`/Maven/Gradle、重建沿用、`jdk use 21` 和失败时保持旧选择。具体测试命令、精确文件步骤及提交策略留给 `cadence/plans/` 中的实施 Plan。
