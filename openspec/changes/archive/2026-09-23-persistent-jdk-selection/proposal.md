# Proposal

## Why

镜像只预装 Java 21，但用户需要完整的 OpenJDK 8 JDK。逐版本维护镜像会放大构建与分发成本；一次性修改容器环境又不能在重建后保留选择，因此需要一个容器内可直接使用、持久记忆版本的入口。

## What Changes

- 实施首先在目标容器环境实测 OpenJDK 8 发行物的可信下载、校验、安装和 `java`、`javac` 运行；未通过则不继续开发切换机制。
- 新增容器内 `jdk` 命令，支持查看已安装版本、选择版本及按需安装缺失版本。
- 首次默认 Java 21；手动切换后记住上次选择，后续进入容器不弹菜单、不指定版本也沿用它。
- 选择对后续新启动的交互命令和非交互容器命令生效，包括 Java、Maven、Gradle；正在运行的 JVM 不变。
- 提供可配置、适合中国大陆网络的 OpenJDK 8 下载源和下载校验；失败时不更改当前版本。
- 不创建 Skill，不按 JDK 版本维护多张镜像，也不根据项目自动切换版本。

## Capabilities

### New Capabilities

- `jdk-selection`: 容器内 JDK 安装、持久化选择、统一命令环境及失败行为。

### Modified Capabilities

无。

## Impact

涉及 devbox 镜像、容器启动环境、Compose 持久卷与安装器、用户操作说明及对应验证。维持现有 Java 21 默认行为；新增 OpenJDK 8 下载依赖受信任的发行源及可配置镜像源，先实测安装可行再实施切换机制。
