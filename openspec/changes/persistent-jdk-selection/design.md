# Design

## Context

设计依据：`cadence/designs/2026-09-23_技术方案_OpenJDK8持久切换_v1.0.md`；参见 proposal.md 的动机与 `specs/jdk-selection/spec.md` 的验收要求。当前镜像以 `JDK_VERSION=21` 从 USTC 的 Adoptium apt 源安装 Temurin，未设置持久 JDK 卷；Compose 已使用 external 命名卷，`install.ps1` 会预建这些卷。当前 `entrypoint.sh` 写入 `.bashrc`，但非交互 `docker exec` 不会读取它。镜像还向 Maven、Gradle 写入国内仓库配置；这些配置不承担 JDK 版本选择。

## Goals / Non-Goals

**Goals:**

- 用一个容器内 `jdk` 命令管理已支持的版本；首次选 21，手动切换后跨容器重建沿用。
- 使交互和非交互新进程读取同一稳定 JDK 入口，不依赖 shell 初始化文件。
- 先实测完整 OpenJDK 8 JDK 可在目标容器环境下载、校验、安装并运行 `java`、`javac`；通过后再按需下载额外 JDK，验证成功后才发布安装与版本选择；可配置国内可达的可信源。

**Non-Goals:**

- 不自动识别项目版本、不提供 Skill、不在容器启动时弹交互菜单，也不在已运行的 JVM 中热切换。
- 不支持未经验证的任意发行版、架构或 Java 主版本；初始支持内置 21 和实测通过的完整 OpenJDK 8 JDK。

## Decisions

### 实施前安装可行性门槛

首个工作包在与目标镜像一致的 Ubuntu 24.04、架构、容器用户权限及中国大陆网络条件下，核对 OpenJDK 8 候选发行版、具体构建、下载端点和独立可信 SHA-256；下载校验后隔离安装，实际运行 `java -version` 与 `javac -version`，均须为 8。记录源、哈希、命令及输出；未通过则停止新增卷、PATH 和切换命令的开发，不能将 HTTP 200 或仅 JRE 的安装当成成功。Temurin 8 与现有 Temurin 21 同系列，可优先作为待测 OpenJDK 8 发行版；若用户指定其他发行商，须先确认再变更选型。尚无已验证的具体国内下载地址。

### 单一命令入口和跨命令生效

`jdk list` 显示内置/额外安装版本与当前选择；`jdk use 8` 或 `jdk use 21` 在成功后切换。镜像设置稳定的 `JAVA_HOME` 为持久卷内的 `current` 路径，并将其 `bin` 排在系统 PATH 前部。`current` 指向所选 JDK（21 可指向镜像内置的 Temurin 目录），由命令以同卷临时链接加原子替换切换。`JAVA_HOME` 字符串不随版本改变，路径解析在新进程启动时获得新目标，`docker exec` 无需读取 `.bashrc`。`jdk list` 的选择状态以 `current` 的有效目标为准，避免配置文件和链接不一致。首次启动只有在未选择时才初始化 `current` 指向 21，不覆盖已有选择。

拒绝仅在 `.bashrc` 中 export `JAVA_HOME`，因为直接 `docker exec java` 不加载它；也不为每个 JDK 发布镜像。已启动的 JVM 使用原版本；正在运行的构建进程若在运行中重新调用 JDK 工具可能看到切换后的版本，操作说明需提醒用户避免在构建中切换。

### 持久化与迁移

新增一个 external 命名卷保存额外 JDK 与 `current`，挂载在固定工具链路径，安装器预建它并在容器内由 `dev` 用户可写；原有的 Maven/Gradle 缓存卷继续原样使用。既有安装升级后新卷为空时自动选择内置 21；原有工作区及缓存不迁移或删除。回滚旧镜像后新增卷保留但旧镜像不读取，恢复新版镜像时沿用选择。若旧镜像不支持新增卷声明，须在升级说明中区分 Compose 与镜像回滚方式。

### 下载与信任

完整 OpenJDK 8 JDK 安装到持久卷的临时目录：只允许明确支持的版本/架构，来源由发行方认可的官方源或显式配置的可信国内镜像选择，固定发行版本并从独立可信元数据取得 SHA-256；不得从同一未受信任镜像同时接受安装包和校验值作为唯一信任依据。安装前对归档校验哈希、解包路径安全性、`bin/java`、`bin/javac` 及实际版本做验证，通过后原子发布目录，再切换 `current`。失败清理临时目录且不触及旧选择；禁止隐式切换未知代理。精确 OpenJDK 8 发行包、国内源路径与可信校验值必须先在首个实施门槛中实测，再写入实施 Plan；在核验前不把任何未经验证的地址设为默认，也不宣称下载链路已可用。

## Risks / Trade-offs

- [可信国内镜像与上游元数据可能不同时可达] → 源与校验信息分离；无法验证则明确失败、保持原选择，支持用户显式配置已验证的可信源，不为可用性放弃校验。
- [命名卷新增导致现有安装流程缺卷启动失败] → 安装器及手工安装指引同步预建卷；既有升级需创建新卷。
- [运行中的 shell 缓存过 `java` 路径或某些进程固定旧 JDK 的真实绝对路径] → 统一公开稳定路径；仅承诺新命令经稳定入口生效，不修改已经固定路径的进程。
- [镜像内置 21 的实际安装路径随镜像变化] → 容器启动时验证 `current` 指向有效安装，升级镜像时对内置版本目标进行兼容迁移；目标失效不得静默使用错误版本。

## Migration Plan

1. 先在目标容器环境实测完整 OpenJDK 8 JDK 下载、可信校验、安装及 `java`、`javac` 运行，并记录证据；失败则停止后续实施并重新审阅来源，不修改镜像和卷。
2. 门槛通过后发布包含固定入口、`jdk` 命令和新增命名卷声明的镜像；安装器为新旧安装创建卷并设置可写权限。
3. 升级时保留旧卷和项目数据；新增卷无状态则初始化为内置 21，已有有效选择不覆盖。验证交互与非交互命令的 Java、Maven、Gradle 行为。
4. 回滚到旧版镜像时 Java 默认回到旧版内置版本，新卷不删除；恢复新版时重新读取有效选择。对兼容性异常明确报错，不擅自重置已有选择。
